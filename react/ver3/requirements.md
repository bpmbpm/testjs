# Техническое задание: VAD Просмотрщик

## 1. Общее описание
Разработать одностраничное веб-приложение (SPA) для просмотра диаграмм в нотации VAD (Value-Added Chain), хранящихся в виде SVG-файлов. Приложение должно работать полностью в браузере без серверной части, поддерживать автоматическую загрузку файлов по URL (с учётом CORS) и ручной выбор файлов с диска.

## 2. Функциональные требования

### 2.1. Загрузка конфигурации
- Приложение должно загружать конфигурацию из внешнего файла `config.js`, который содержит:
  - `svgPath` – строка с URL-путь к папке с SVG-файлами.
  - `files` – массив имён файлов (с расширением `.svg`), которые будут отображаться в дереве.
  - `defaultExpanded` – булев флаг, определяющий, развёрнуты ли все папки по умолчанию.
- Конфигурация должна быть доступна глобально через `window.CONFIG` и дублироваться в виде YAML-строки в `window.CONFIG_YAML` для документации.
- Если `config.js` не загружается (ошибка сети, отсутствие файла), приложение должно перейти в ручной режим (см. п. 2.5).

### 2.2. Построение дерева файлов
- На основе списка имён файлов (`files`) строится иерархическое дерево.
- Правило построения: если имя содержит дефис (например, `file1-1.svg`), то первая часть до дефиса считается именем родителя (`file1.svg`). Если родитель отсутствует в списке, файл становится корневым.
- Корневой элемент (невидимый) называется `Корень` и содержит все корневые узлы.
- Каждый узел имеет уникальный `id` (равный имени файла), отображаемое имя (с расширением `.svg`), флаг `loaded` (загружено ли содержимое), поле `children` (массив id дочерних узлов), `svgContent` (текст SVG), `properties` (объект свойств) и `stages` (массив этапов).

### 2.3. Интерфейс
Приложение должно содержать четыре основных окна (компонента), расположенных в сетке:

1. **Дерево файлов (TreeView)**
   - Отображает иерархию в виде раскрывающегося списка.
   - Каждый узел отображается с иконкой: 📁 для папок (узлов с детьми), 📄 для файлов (листьев).
   - Рядом с именем отображается статус: `⬇️` для незагруженных файлов, `✅` для загруженных.
   - Панель инструментов содержит:
     - Поле поиска (фильтрация узлов по имени).
     - Кнопки «Развернуть всё» и «Свернуть всё».
     - Кнопка «Обновить» (перезагрузка списка файлов).
   - При клике на узел (кроме клика по шеврону) узел становится выбранным, и в лог добавляется запись (только для файлов, не для папок).
   - При клике по шеврону узел раскрывается/сворачивается, и в лог добавляется соответствующее событие.

2. **Свойства (Properties)**
   - Отображает свойства выбранного узла.
   - Если выбран файл и он загружен, показываются:
     - Количество этапов.
     - Список этапов (через стрелку →).
     - Длительность (план) = количество этапов × 2 дня.
     - Ответственный, версия, дата создания, тип диаграммы.
   - Если файл не загружен – сообщение «Свойства не загружены».
   - Если выбран папка – отображается её тип и статус загрузки.

3. **Диаграмма (Diagram)**
   - Отображает SVG-содержимое выбранного файла (если загружено).
   - Если файл не выбран – placeholder с предложением выбрать.
   - Если выбран файл, но он не загружен – placeholder с предложением нажать для загрузки.
   - Если выбран папка – сообщение «Это папка, выберите файл внутри».
   - При клике по области диаграммы:
     - Если файл не выбран – показывается всплывающее сообщение «Не выбран элемент treeview».
     - Если выбран файл и он не загружен – инициируется загрузка (автоматическая или ручная).
     - Если файл загружен – в лог добавляется запись «Просмотр диаграммы "имя"».
   - Клик по области с ошибкой сбрасывает ошибку.

4. **Лог действий (Log)**
   - Отображает хронологию всех событий с временем (ЧЧ:ММ:СС).
   - Группы событий: «Система», «Выбор», «Загрузка», «Диаграмма», «Дерево», «Поиск», «Ошибка».
   - Логируются:
     - Загрузка файлов из папки.
     - Выбор файла.
     - Загрузка SVG.
     - Просмотр диаграммы.
     - Раскрытие/сворачивание узлов.
     - Поиск.
     - Ошибки.
     - Действия с ручным выбором файлов.

### 2.4. Загрузка содержимого SVG
- **Автоматический режим:** если в конфиге указан `svgPath` и список `files`, приложение строит дерево и при клике на файл пытается загрузить его через `fetch` по URL `svgPath + fileName`. Если загрузка успешна, содержимое парсится, извлекаются этапы и свойства, узел помечается как загруженный.
- **Ручной режим:** если автоматическая загрузка невозможна (CORS, отсутствие списка или ошибка), приложение переключается в ручной режим, где пользователь может выбрать SVG-файлы с диска через диалог (multiple). После выбора файлы читаются через `FileReader`, дерево строится, и каждый файл сразу загружается.
- При любой загрузке (автоматической или ручной) из SVG-кода извлекаются названия этапов (поиск всех текстовых элементов, кроме служебных), формируются свойства и обновляется состояние узла.

### 2.5. Обработка ошибок и CORS
- Если `fetch` для загрузки SVG возвращает ошибку (особенно CORS), приложение должно автоматически переключаться в ручной режим, предлагая пользователю выбрать файлы вручную.
- Если конфиг не загружается, также включается ручной режим.
- Все ошибки должны быть показаны в интерфейсе (всплывающее сообщение или в логе).

### 2.6. Сохранение состояния
- При первом запуске, если используется ручной режим, после выбора файлов дерево строится и данные хранятся в памяти.
- Повторная загрузка страницы приводит к перезагрузке конфига и повторному построению дерева (автоматическая загрузка или повторный ручной выбор).

## 3. Технические требования

### 3.1. Стек технологий
- **React 18** (без использования JSX-транспиляции в коде, но допускается использование Babel для разработки).
- **ReactDOM 18**.
- **Babel Standalone** для трансформации JSX в браузере (используется в итоговом коде).
- **File API** (FileReader) для чтения файлов с диска.
- **IndexedDB** для хранения `FileSystemDirectoryHandle` (не используется в финальной версии, но может быть).
- **Fetch API** для загрузки файлов по URL.
- **DOMParser** для парсинга SVG.
- **localStorage** не используется.

### 3.2. Структура файлов
- `index.html` – основная страница, содержит подключение React, Babel, встроенный основной код.
- `config.js` – внешний конфигурационный файл (загружается динамически).
- `styles.css` – файл со всеми стилями (подключается в `index.html`).

### 3.3. Кроссплатформенность
- Приложение должно работать в браузерах с поддержкой File System Access API (Chrome, Edge) для ручного выбора папки (не обязательно, т.к. используется выбор отдельных файлов).
- Автоматическая загрузка по URL работает в любом браузере, но ограничена политикой CORS.

## 4. Дизайн и UI
- Использовать предоставленные стили (светлая тема, скруглённые углы, тени).
- Окна должны быть разделены сеткой: слева – дерево и свойства, справа – диаграмма, внизу – лог.
- Адаптивность не требуется, но желательна.

## 5. Критерии приёмки
- Приложение запускается без сервера (локально).
- При наличии `config.js` и доступных URL файлы загружаются автоматически при клике.
- При отсутствии `config.js` или ошибках CORS включается ручной режим.
- Все действия (выбор, раскрытие, загрузка, просмотр) логируются.
- SVG-диаграмма отображается корректно, свойства извлекаются.
- Интерфейс соответствует описанию.

## 6. Требования к коду
- Код должен быть разделён на логические группы с комментариями.
- Все функции должны быть чистыми, где возможно.
- Использовать функциональные компоненты React и хуки (`useReducer`, `useEffect`, `useCallback`).
- Состояние управляется через `useReducer` с явными типами действий.
- Избегать прямых манипуляций с DOM.
- Обрабатывать все возможные ошибки и показывать их пользователю.
