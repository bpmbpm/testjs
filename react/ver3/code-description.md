# Подробное описание кода VAD Просмотрщика

## Общая структура
Код представляет собой одностраничное React-приложение, которое выполняется в браузере. Используется Babel Standalone для трансформации JSX в обычный JavaScript. Все функции сгруппированы по логическим блокам (группам), каждая группа имеет своё назначение и использует определённые библиотеки/API.

---

## Группа 1: Утилиты для работы с файлами и SVG
**Назначение:** обработка SVG-кода, извлечение этапов, построение дерева.

### Функция `extractStagesFromSVG(svgText)`
- **Группа:** Утилиты
- **Библиотеки/API:** `DOMParser`, `querySelectorAll`
- **Описание:** принимает строку с SVG-кодом, парсит её, находит все элементы `<rect>` и `<text>`, извлекает названия этапов из текстов, игнорируя служебные надписи (содержащие «Количество этапов» или «диаграмма»). Если количество текстов совпадает с количеством прямоугольников минус один (фон), возвращает их. Иначе генерирует имена «Этап 1», «Этап 2» ... по числу прямоугольников (минимум 5).
- **Возвращает:** массив строк.

### Функция `extractPropertiesFromSVG(svgText)`
- **Группа:** Утилиты
- **Библиотеки/API:** вызывает `extractStagesFromSVG`
- **Описание:** формирует объект свойств на основе этапов: количество этапов, их список (через →), длительность (этапы × 2 дня), ответственный, версия, дата создания, тип диаграммы.
- **Возвращает:** объект с указанными ключами.

### Функция `buildTreeFromFileNames(fileNames)`
- **Группа:** Утилиты
- **Библиотеки/API:** стандартный JavaScript (массивы, объекты)
- **Описание:** принимает массив полных имён файлов (с расширением `.svg`). Строит иерархическое дерево: для каждого имени создаёт узел. Определяет родителя по правилу: если в имени есть дефис, то часть до дефиса + `.svg` считается родителем. Если родитель отсутствует, узел становится корневым. Создаёт корневой узел «Корень» со списком корневых id.
- **Возвращает:** объект `data`, где ключ – id узла, значение – узел (с полями `id`, `name`, `children`, `loaded`, `svgContent`, `properties`, `stages`).

## Группа 2: Управление состоянием (Reducer)
**Назначение:** хранение и обновление состояния приложения.

### Константы `ACTION_TYPES`
- **Группа:** Состояние
- **Описание:** объект со строками-типами действий: `SELECT_FILE`, `CLICK_DIAGRAM`, `CLEAR_ERROR`, `LOG`, `SET_FILES`, `LOAD_SVG`, `EXPAND_ALL`, `COLLAPSE_ALL`, `SET_EXPANDED`, `SET_FOLDER_PATH`, `SET_LOADING`, `SET_MANUAL_MODE`.

### Функция `createLogEntry(group, message)`
- **Группа:** Состояние
- **Библиотеки/API:** `Date`
- **Описание:** создаёт объект записи лога с текущим временем (ЧЧ:ММ:СС), группой и сообщением.

### Объект `INITIAL_STATE`
- **Группа:** Состояние
- **Описание:** начальное состояние приложения:
  - `data: null` – дерево узлов.
  - `selectedFile: null` – id выбранного узла.
  - `uiState: 'NO_SELECTION'` – состояние UI (NO_SELECTION, FILE_SELECTED, ERROR_NO_SELECTION).
  - `errorMessage: null`.
  - `logs: []` – массив записей лога.
  - `expandedIds: new Set()` – множество id раскрытых узлов.
  - `searchQuery: ''`.
  - `folderPath: ''`.
  - `fileHandles: {}` – для ручного режима (File объекты).
  - `isLoading: false`.
  - `manualMode: false` – флаг ручного режима.

### Функция `appReducer(state, action)`
- **Группа:** Состояние
- **Библиотеки/API:** чистая функция
- **Описание:** обрабатывает все действия и возвращает новое состояние. Обрабатывает:
  - `SET_LOADING`: установка флага загрузки.
  - `SET_FOLDER_PATH`: сохранение пути.
  - `SET_FILES`: построение дерева, установка `data`, `expandedIds`, `fileHandles`, добавление записи в лог.
  - `SELECT_FILE`: выбор узла, логирование только для файлов (не папок), сброс ошибки.
  - `LOAD_SVG`: загрузка содержимого, извлечение свойств, обновление узла, лог.
  - `CLICK_DIAGRAM`: обработка клика по диаграмме, логирование просмотра, генерация ошибки при отсутствии выбора.
  - `CLEAR_ERROR`: сброс ошибки.
  - `LOG`: добавление произвольной записи в лог.
  - `EXPAND_ALL` / `COLLAPSE_ALL`: установка множества раскрытых узлов.
  - `SET_EXPANDED`: явная установка множества.
  - `SET_MANUAL_MODE`: переключение ручного режима.

## Группа 3: Загрузка конфигурации и файлов
**Назначение:** загрузка внешнего конфига и SVG-файлов (автоматическая и ручная).

### Функция `loadConfig()` (внешняя, в теге `<script>`)
- **Группа:** Загрузка
- **Библиотеки/API:** динамическое создание `<script>`.
- **Описание:** создаёт тег `<script src="config.js">` и возвращает Promise. При успешной загрузке `window.CONFIG` становится доступен. Если не загрузился – reject.

### Функция `loadFileList(config)`
- **Группа:** Загрузка
- **Библиотеки/API:** `fetch`, работа с массивами.
- **Описание:** принимает объект конфига. Если в нём есть поле `files` (массив), возвращает массив объектов `{ name, url }` (url = svgPath + name). Если поля нет, пытается загрузить `index.json` по адресу `svgPath + 'index.json'` и извлечь список оттуда. В случае неудачи возвращает пустой массив.

### Функция `loadSVGFromURL(url)`
- **Группа:** Загрузка
- **Библиотеки/API:** `fetch`
- **Описание:** выполняет GET-запрос по URL и возвращает текст ответа. В случае ошибки выбрасывает исключение.

### Функция `loadSVGByURL(fileId)` (внутри компонента App)
- **Группа:** Загрузка
- **Библиотеки/API:** `fetch`, `dispatch`
- **Описание:** загружает SVG по URL, сохранённому в `window.__FILE_URLS[fileId]`, и диспатчит `LOAD_SVG` с полученным текстом. При ошибке (особенно CORS) переключает в ручной режим и логирует.

### Функция `handleManualFiles(files)` (внутри компонента App)
- **Группа:** Загрузка
- **Библиотеки/API:** `FileReader`, Promise.all
- **Описание:** принимает массив объектов `File`, выбранных пользователем. Через `FileReader` читает каждый файл как текст, сохраняет содержимое в `window.__MANUAL_SVG_CONTENT`, строит дерево через `SET_FILES` и для каждого файла диспатчит `LOAD_SVG`.

## Группа 4: React-компоненты
**Назначение:** рендеринг интерфейса, обработка событий.

### Компонент `LoadingScreen`
- **Группа:** UI
- **Библиотеки:** React
- **Описание:** отображает анимацию загрузки.

### Компонент `ManualFileSelector`
- **Группа:** UI
- **Библиотеки:** React, File API
- **Описание:** позволяет пользователю выбрать несколько SVG-файлов через `<input type="file" multiple>`. При нажатии кнопки «Загрузить» вызывает `onFilesSelected` с массивом выбранных файлов.

### Функция `renderTreeNodes`
- **Группа:** UI (вспомогательная для TreeView)
- **Библиотеки:** React
- **Описание:** рекурсивно рендерит узел дерева и его дочерние элементы. Фильтрует по поисковому запросу. Отображает иконку, имя, статус, шеврон (для папок). При клике по узлу вызывает `onSelect`, при клике по шеврону – `onToggle`.

### Компонент `TreeViewComponent`
- **Группа:** UI
- **Библиотеки:** React
- **Описание:** отображает панель инструментов (поиск, кнопки) и список корневых узлов, используя `renderTreeNodes`. Принимает пропсы: `data`, `expandedIds`, `selectedFile`, `searchQuery`, обработчики.

### Компонент `PropertiesComponent`
- **Группа:** UI
- **Библиотеки:** React
- **Описание:** отображает свойства выбранного узла. Если узел отсутствует – сообщение о выборе. Если узел есть – рендерит пары ключ-значение из `properties`, а также тип узла и статус загрузки.

### Компонент `DiagramComponent`
- **Группа:** UI
- **Библиотеки:** React
- **Описание:** отображает SVG-содержимое (через `dangerouslySetInnerHTML`), placeholder для разных случаев (не выбран, папка, не загружен). При клике вызывает `onDiagramClick`. Показывает всплывающую ошибку, если `errorMessage` не null.

### Компонент `LogComponent`
- **Группа:** UI
- **Библиотеки:** React
- **Описание:** отображает все записи лога в виде таблицы с временем, группой и сообщением.

### Компонент `ToastMessage`
- **Группа:** UI
- **Библиотеки:** React
- **Описание:** всплывающее сообщение об ошибке (показывается, если `visible === true`).

### Компонент `App`
- **Группа:** UI (корневой)
- **Библиотеки:** React, `useReducer`, `useEffect`, `useCallback`
- **Описание:** основной компонент, содержит состояние и всю бизнес-логику. Инициализирует загрузку конфига и файлов через эффекты. Обрабатывает выбор узла, клик по диаграмме, раскрытие/сворачивание, поиск, ручной выбор файлов. Рендерит макет с четырьмя окнами.

## Группа 5: Вспомогательные сервисы (IndexedDB)
**Назначение:** сохранение доступа к папке (в текущей версии не используется, но код присутствует).  
*(В финальной версии мы отказались от использования IndexedDB в пользу ручного выбора файлов, но оставили функции для возможного расширения.)*

### Функции `openDB`, `saveHandle`, `loadHandle`
- **Группа:** Сервисы
- **Библиотеки/API:** `indexedDB`
- **Описание:** позволяют сохранять и восстанавливать `FileSystemDirectoryHandle` для автоматического восстановления доступа к папке при повторных запусках. В текущей реализации не задействованы.

## Библиотеки и зависимости

| Библиотека/API | Назначение |
|----------------|------------|
| React 18 | Построение пользовательского интерфейса (функциональные компоненты, хуки). |
| ReactDOM 18 | Рендеринг React-компонентов в DOM. |
| Babel Standalone | Трансформация JSX в обычный JavaScript в браузере (используется в `script type="text/babel"`). |
| DOMParser | Парсинг SVG-строки для извлечения этапов. |
| Fetch API | Загрузка конфига и SVG-файлов по URL. |
| FileReader | Чтение содержимого файлов, выбранных пользователем. |
| IndexedDB | (Опционально) для хранения handle (не используется в финале). |
| window.showDirectoryPicker | (Опционально) для выбора папки (не используется). |

## Особенности реализации

- **Отказ от JSX-синтаксиса в пользу `React.createElement`** – так код работает без Babel в production, но для удобства разработки в коде используется JSX, который транслируется Babel на лету.
- **Обработка CORS** – если `fetch` не удаётся, приложение переключается в ручной режим, что гарантирует работу даже при строгих CORS-политиках.
- **Логирование** – все значимые события записываются в лог с временем, что упрощает отладку.
- **Чистые функции** – утилиты для извлечения этапов и построения дерева не имеют побочных эффектов.
- **Модульность** – код разбит на группы, каждая группа отвечает за свою область.

## Заключение
Данное описание позволяет полностью воспроизвести код приложения, следуя техническому заданию и используя указанные библиотеки. Для запуска достаточно сохранить `index.html`, `config.js` и `styles.css` и открыть `index.html` в браузере (желательно через локальный сервер, чтобы `config.js` корректно загружался, но и без сервера приложение перейдёт в ручной режим).
